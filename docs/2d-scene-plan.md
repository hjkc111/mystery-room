# 2D 场景玩法改版方案

## 1. 目标与验收

将当前四人剧本杀从表单式页面改为可行走的俯视像素游戏，同时保留角色本、分幕信息、个人证据、投票、AI 主持与 AI 玩家。玩家进入游戏后首先看见场景，不再通过远程调查按钮取得证据。

必须可完成：创建房间、四人或真人与 AI 入席、按阶段进入场景、WASD/方向键移动、靠近地面线索按空格调查、进入双人会客室私聊、全部搜证门槛、秘密指控、结案。手机提供方向按钮与交互键；输入文本时不触发移动或搜证。

## 2. 阶段与场景

| 阶段 | 默认场景 | 可进入范围 | 核心操作 |
|---|---|---|---|
| 围桌准备 | 大厅 | 大厅 | 选择角色、配置 AI、准备 |
| 身份与秘密 | 阅览室 | 阅览室 | 阅读个人角色本，准备 |
| 开场陈述 | 大厅大桌 | 大厅 | 同场景聊天、自我介绍 |
| 初次搜证 | 庭院 | 庭院、水潭岸、农场书房、大厅、两间会客室 | 走近个人与公共线索，空格调查 |
| 交换质询 | 大厅 | 大厅、两间会客室 | 公布个人证据；同室私聊 |
| 深入调查 | 庭院 | 同初次搜证 | 找到四份第二轮复核材料 |
| 最终陈述 | 大厅 | 大厅、两间会客室 | 核对公开材料、发言 |
| 秘密指控 | 大厅 | 大厅 | 独立提交选票 |
| 结案 | 大厅 | 大厅 | 展示真相和个人结果 |

场景采用 768×480 逻辑坐标，32 像素瓦片。大桌、柜子、树木、水面、墙体设碰撞区，门为明确的交互区域。门只通向本阶段允许场景；切幕后服务器将位置重置到该阶段出生点。后台旧位置不能让玩家留在已关闭场景。

## 3. 操作与呈现

- WASD/方向键移动，斜向归一化，速度 160 像素/秒；空格与画面上的交互按钮执行最近可交互目标。移动只在画布聚焦时生效，离焦/隐藏页面清空按键。
- 首屏以地图为主，顶栏显示房间、阶段、倒计时和连接质量；右侧为当前场景讨论。角色本、证据、投票和主持为可切换的工具面板，保留阅读字号和完整内容。
- 玩家显示角色精灵、名字、本人标识与 AI 标识；只在同一场景绘制彼此。名册可查看其他人所在场景和离线状态。
- 地面线索使用素材图标与高亮范围。未解锁的线索不下发内容；已经调查、无行动点或非自己个人线索时，服务器拒绝操作。交互距离目标为 56 像素。
- 搜证成功后打开个人证据内容；公开证据仍需主动操作，原阶段规则保持。
- 手机使用可按住的方向按钮、空格等价交互键，布局上下排列且无水平溢出。

## 4. 实时通信

现有 Sites 的公开部署契约提供 Worker + D1，没有可在项目配置中声明的房间 Durable Object。本版不假设 Worker 内存能跨实例共享，也不新增需要购买或登录的外部服务。

- WebRTC DataChannel 全连接最多四位真人，传输位置和状态更新通知；不传密钥、完整剧本、证据正文、私聊或选票。
- 有身份校验的同源接口交换 SDP，D1 保存每对玩家最新信令。较小玩家 ID 发起连接，避免双方同时发起的冲突；断线后重建，信令有过期时间与长度限制。
- 浏览器渲染约 60 FPS，移动数据最多 20 Hz；本地输入立即反馈，远端插值平滑。通道缓冲过高时丢弃旧位置，避免积压。
- 服务器以较低频率保存有效移动轨迹，验证速度、碰撞、阶段、门与会客室容量。速度使用两秒上限的累计距离预算容忍网络抖动，顺序号 CAS 避免并发重复使用额度。关键操作前同步位置，搜证和私聊始终由服务端裁决，P2P 坐标不授予权限。
- WebRTC 不通时使用 HTTP 位置同步和状态轮询；移动/消息发送后优先刷新，平时控制请求频率。网络错误明确显示并自动恢复，恢复后以服务器状态校准。
- 使用公共 STUN 辅助直连，不预设 TURN 中继可用。跨运营商/严格 NAT 下可能回退 HTTP，本版不能承诺所有网络都达到固定毫秒延迟。
- 显示通道数与实测 RTT。验收记录区分同机四浏览器、故障回退和公网测试，不将本机测量当公网保证。

## 5. 场景与聊天权限

- 普通场景中的聊天只显示该场景记录。
- 每间私人会客室最多两人；门口进入请求由数据库条件写入检查容量，三个并发请求最多两人成功。
- 同处会客室的两人发送消息时自动指定对方，移除跨场景任意私聊下拉选择。空会客室等待第二位玩家；第三人无法进入。
- 私聊记录仍保存明确收发者，后来进入该会客室的人不能读取此前两人的聊天。历史分页与 AI 上下文都应用相同权限过滤。
- AI 可被邀请到当前会客室；AI 公聊只读取公共讨论，私聊只读取与当前玩家的对话。AI 回复过程中离开房间时取消私聊回复。
- 聊天请求和搜证请求不接受客户端伪造角色身份；页面隐藏不是权限控制。

## 6. AI 与现有存档

- 保留开局前手动设置 AI、@对话及房主触发本幕行动。
- AI 的调查仍遵守行动点和原证据条件；服务端记录 AI 到达相应目标的位置，地图显示其调查场景。不会将未调查线索直接公开。
- 旧房间未存位置时按当前阶段初始化，不改变角色、线索、消息和投票。数据库只追加迁移，旧迁移不改写。
- 旧的远程调查入口改为显示目标场景与“走近后空格调查”；已有关键游戏规则复用。

## 7. 素材和实现边界

优先使用 Kenney CC0 俯视素材，同一图集统一地面、家具和角色；保留原许可和来源。原图缓存到项目静态资源内，发布后不依赖第三方热链。不加入音视频聊天、匹配大厅、商业剧本库或新剧情。

采用原生 Canvas 2D、浏览器 WebRTC、现有 ES 模块和 D1。共享纯数据地图/碰撞模块用于前后端一致校验；不要把 server/case.mjs 打包到前端。构建静态白名单支持必要 PNG 和模块资源。

## 8. 测试矩阵

| 层级 | 必测项目 | 通过标准 |
|---|---|---|
| 原规则回归 | 四人流程、权限、阶段门槛、投票、AI 去重 | 原有测试继续通过，空间规则测试同步更新 |
| 地图单元 | 边界、桌子/水面碰撞、斜向速度、出生点、门连接 | 非法坐标被拒绝，出生点均可行走 |
| 空间接口 | 身份、越界、超速、跨场景瞬移、旧阶段移动、远程搜证 | 无奖励/无扣点/无秘密泄露 |
| 会客室 | 三人同时进门、离开、换幕、历史消息、伪造收件人 | 容量两人且非当事人无消息 |
| 信令 | 房外访问、冒充发送者、过长 SDP、过期会话 | 拒绝且不回传凭据 |
| 浏览器交互 | 四个隔离身份、键盘、墙壁、门、空格、输入框、工具面板 | 通过实际 UI 操作，控制台无异常 |
| 实时 | 四浏览器位置互见、RTT、断线重连、强制禁用 WebRTC | 记录实际延迟，回退后仍可移动和完成操作 |
| 移动端 | 390px 视口、方向按钮、交互、聊天与读本 | 无水平溢出、按钮可用 |
| 混合 AI | 真人+AI、@、会客室邀请、阶段调查与投票 | 不阻塞完整结案 |
| 发布 | 同源资源、迁移、健康检查、真实线上房间 | 原网址提供新版且权限仍正确 |

测试不得靠提前改数据库让浏览器假装完成行走。单元/接口层可使用独立测试数据验证边界，浏览器测试必须实际按键和交互。

## 9. 实施顺序与交付

1. 写方案、核实部署约束、准备素材。
2. 实现共享地图和服务端空间权限、追加迁移。
3. 实现场景画布、输入、门与搜证，交付第一个可操作预览。
4. 接入 WebRTC 与回退、同场景聊天、私人会客室、AI 适配。
5. 执行测试、修复失败、形成带证据的测试报告；记录实际限制。
6. 提交 GitHub、发布到原 Sites 公开网址并完成公网检查。
