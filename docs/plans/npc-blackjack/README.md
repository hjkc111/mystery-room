## 1. 目标、范围和验收定义

三个交付目标：

1. AI 成为能自主选择活动、实际沿路行走、抵达后搜证、与同场景玩家交流的 NPC，不再依赖房主每幕点击“完成”。
2. 庄园内加入可入座的 21 点桌，支持真人对真人、真人对 AI；另做一个小型“记忆翻牌”作为单人等候游戏。二者均不能卡住剧本主线。
3. 从当前平铺、空旷的地图升级为统一像素风的雨夜庄园，改善场景层次、人物动画、交互反馈和手机可读性。素材必须免费且允许项目使用、修改和公开仓库再分发。

本版不加入真钱、付费筹码、商城、跨房间排行榜、语音视频、无限世界、额外剧本或全新的前端框架。21 点中的“对战”采用下文明确的双人比点规则，不把常见的“所有玩家各自挑战庄家”冒充人人直接对战。

需求追踪：

| 编号 | 用户要求 | 实施内容 | 必须看见的验收结果 |
|---|---|---|---|
| R1 | NPC 自己走来走去 | 自主决策、跨场景寻路、到达交互、空闲活动 | 不点击房主行动按钮，连续录屏可见 NPC 绕桌、过门、停在证据处调查 |

## 4. 自主 NPC 行为设计

### 4.1 三层职责

- **规则和信息层**：生成该 NPC 真正能看到的章节、证据、同场景人物、公开消息或当前私聊；列出当前合法行动。不得将完整 room、CASE、其他角色秘密、未解锁证据或牌堆传给模型。
- **决策层**：程序处理常规优先级；在重要事件下由大模型从合法行动里选择目标、组织角色发言和推理。模型不控制每帧坐标。
- **执行层**：程序计算路径、同步行走、处理门/座位容量；抵达后再次检查规则并提交调查/聊天/准备。动画和权限使用同一条权威路线。

没有 API Key 或模型失败时，NPC 仍会沿路完成规则允许的必需动作，发言明确标为规则代行，不伪称大模型已推理。投票失败时明确显示“本次未能形成指控”，允许真人再次提问；若截止前仍无有效选票，沿用现有截止后的未投票结算，不读取答案来保证猜中，也不提前跳过真人。

### 4.2 可观察状态与优先级

状态：`idle → deciding → walking → interacting → cooldown`，另有 `talking / seated / paused / waiting_for_space`。玩家只看见简短活动描述和所在场景，不能看内部推理、隐藏目标或未公开线索名称。

优先级从高到低：阶段切换/暂停 → 正在处理的有效 @ 或私聊 → 必需个人调查/分享/投票 → 已接受的邀请 → 可选调查 → 普通社交 → 等候或小游戏。

- 切幕取消旧路线、过期邀请和旧模型任务；不能在新幕交付上一幕的调查奖励。
- 真人 @ NPC 时，NPC在最近可停的路径点停步、面向说话者；回应后恢复仍有效的任务。私聊中不响应房外公开 @，房外玩家看到“正在会谈”。
- 空闲 NPC 在场景的少量兴趣点之间停留 5–12 秒；不随机全图乱跑，不堵门、不在证据上永久停住。
- 同一 NPC 同时只有一个主任务。牌桌入座/会议接受会取消普通漫游；主线必要行动优先于娱乐。
- 自我介绍采用房间发言队列，单次约 1–3 句，NPC 自动公开发言至少间隔 12 秒；真人插话不阻塞。
- 房主可暂停/恢复单个 NPC 的自主模式、召集回大厅。召集仍然寻路；不能凭这个控制读取它的秘密。保留旧房间手动模式。

### 4.3 决策接口与可追踪结果

计划输入概念：`phase, publicRole, ownChapters, ownClues, observedPeople, permittedHistory, legalActions, currentTask`。history 限制条数，并区分系统证据、玩家陈述和模型猜测。

计划输出示例（只是约定，尚非现有 API）：

```json
{"action":"investigate","targetId":"one-authorized-target","speech":null}
```

允许 `move_to / investigate / say / accept_invite / publish / ready / vote / play_cards / wait`。每次一个动作；speech 不能顺带执行第二个动作。未知字段、越权目标、无效 JSON、超时都不能产生游戏副作用。无效任务不无限重试，最多重计划一次，随后规则代行或短暂等待。

模型返回时重新验证 `phase + taskVersion + leaseToken + 可见材料版本`。被真人叫停、暂停、换幕、离桌后，迟到答案不能重新启动旧任务。服务端保留短的结构化动作结果与原因，不保存/显示模型思维链。

### 4.4 寻路与抵达

- 场景间用现有门连接图做 BFS；场景内对共享碰撞网格做四邻接 BFS，先沿格子中心走，再连接可达终点。七/八张小地图无需引入导航框架。
- NPC 使用相同身体半径、碰撞和交互距离。路径节点压缩后，每个线段都用 `clearPath()` 再验证。
- 保存权威路径段、开始时刻、速度、目标和版本。所有客户端从服务端时间计算同一进度；刷新或真人房主离开不会让 NPC 回到起点。
- 过门在抵达门口后提交空间操作；目标房间出生点要合法。进会议室需要邀请/容量预留，走到时再次确认，不可强行挤入。
- 调查前计算服务器真实当前位置，必须在 56 像素交互范围。执行一次且仅扣一次 AP。模型选中证据并不等于获得证据。
- 目标失效或路线堵住时重算一次；仍不可达就清空任务并显示等待原因。禁止静默瞬移完成调查。仅切幕重置和明确故障恢复可以调整位置，并且不能附带奖励。
- 人物之间不设硬碰撞，避免狭窄门口互卡；家具、水面等静态碰撞严格生效。座位和会客室容量由服务器限制。

### 4.5 自动运行和服务端约束

当前部署不能假定 Worker 会永远运行。采用“在线玩家驱动、有持久化租约的短 tick”：

1. 当前在线前台真人中选一个协调客户端，约每 2 秒发出 tick；它只是提醒服务器，没有 AI 行动权限。其他客户端可在租约过期后接替，不能依赖房主标签页永远开着。
2. D1 以条件写入认领到期工作，同房间一次最多一个模型任务；房间内其他 NPC 可继续已安排的行走。
3. 到点位置由路径与服务器时刻推导，tick 只结算抵达/下一任务，不在 D1 每秒写 60 帧。NPC 坐标不接受真人伪造的 P2P 消息。
4. 模型调用独立于普通 GET /state；短 POST 等待一次调用，20 秒超时，25 秒租约，迟到结果需令牌校验。耗尽租约由下个在线 tick 回收。
5. 全部真人离线超过 20 秒时，停止新任务及新模型调用。返回后只校准当前路径和一次状态，不补跑离线期间几十轮搜证/对话。主线计时沿用现有行为，不擅自改成全局自动暂停。
6. 不把 `setInterval` 或长 `waitUntil()` 当作常驻 NPC 服务。Cloudflare 对响应后的 `waitUntil` 有 30 秒延长期限制；该事实不等于 Sites 已提供 Queues/DO 配置。后续若要无人在线仍持续运行，需要另行核实托管能力。

来源：[Cloudflare Context](https://developers.cloudflare.com/workers/runtime-apis/context/)。上面 tick/租约是本项目方案，不是声称平台自带了这个功能。

### 4.6 调用预算

保留现有每局总预算默认 80 次。自主决策最多 24 次、每 NPC 最多 8 次，且保留最后 24 次给真人主动提问/对话；失败调用也计数。自动模型请求至少相隔 45 秒，只有新阶段、新重要材料、必须发言或投票时触发，普通走路和漫游不调用模型。

每幕通常一次决策，首轮搜证可多一次。预算耗尽后继续规则行动；UI 显示“自主推理预算已用完，规则行动继续”，不能让 NPC 原地卡死或无限花费。数值是开发初始值，不是已测得的最优参数，设置表统一维护。

## 5. 21 点：完整游戏规则

### 5.1 模式和入座

名称“庄园 21 点 · 双人对决”。一张桌两席，每场固定 3 小局。胜一局得 1 分，平局各 0.5 分；三局总分高者胜，分数相同整场平局。只记录这一场比分，没有下注、充值或可兑换奖励。

真人模式：靠近桌子按空格入座 → 发出邀请/等待另一真人 → 双方准备。人机模式：选择当前可接受邀请的 AI 角色，它实际走到桌边并入座后开始。忙于主线或私聊的 NPC 可拒绝；不能把剧本角色复制成另一个牌桌分身。AI 角色在准备阶段也可参与，无 Key 时使用固定牌局策略。

其他玩家只能看见“空桌/等待/对局中、玩家名字、当前局数、已结算比分”。初版不开放暗牌旁观或桌外代操作。

### 5.2 牌、点数与胜负

- 每小局独立洗一副 52 张标准牌，不含大小王。服务端 CSPRNG + 无偏随机整数驱动 Fisher–Yates；不使用客户端随机数决定发牌，不把牌堆/随机种子提前下发。
- 开始时按 A、B、A、B 的顺序各发两张，先发席位每小局轮换。两位玩家只看自己的牌；结算前对方只显示统一牌背及“考虑中/已停牌/已结束”，不暴露具体点数或爆牌原因。
- 2–10 按牌面，J/Q/K 算 10，A 优先算 11，超过 21 时逐张 A 减 10，尽量取得不爆牌的最大点数。
- 初始两张 A + 十点牌称“天生 21 点”。它胜过三张或更多组成的 21；双方天生 21 为平局。
- 玩家各自可“要牌”或“停牌”，无需轮流等对方。到 21、天生 21、或爆牌后自动结束自己的决策。其余情况下必须主动停牌或超时。
- 双方均结束后统一揭牌：一方爆牌则另一方胜；双方爆牌平局；均未爆牌先比较天生 21，再比较点数；点数相同平局。
- 没有庄家、分牌、加倍、保险、五小龙、花色大小。规则入口在准备页和牌桌内均可打开，明确这是本项目比点玩法。
- 同一小局不会重用已发出的牌。尽管理论最多 52 张，仍需处理牌堆耗尽：系统终止小局、不计分并记录异常，不生成重复牌凑数。

点数样例：A+A+9=21；A+6=17（软17）；A+6+K=17（硬17）；K+Q+2=22 爆牌；初始A+K胜7+7+7；双方22平局。

### 5.3 时限、离席与断线

每小局总决策时间 45 秒，从发牌完成开始，不因不断要牌重置。时间到自动停牌；若已爆牌保持爆牌。双方结束后展示结果 6 秒，随后进入下一小局；最后展示整场结果。

开始前邀请 20 秒过期、准备等待 30 秒过期，释放空闲席。开始后刷新恢复本人手牌和倒计时；断线 20 秒仍可恢复，超过则该离线玩家本场弃权。双方都离线或主线切幕，整场取消不计整场胜负。主动离席先提示会弃权，再提交；点击关闭面板只收起面板，不能偷偷离席。

暂停按剩余时间恢复；服务端决定超时，客户端改时钟没有用。并发命令在条件写入中排定顺序；相同 requestId 重放返回同一结果，不能多抽一张。过期 expectedRevision 返回最新本人视图并允许明确重试，不自动重复“要牌”。

### 5.4 AI 对手

首版牌局策略为确定性的有限信息规则，不依赖大模型等待：硬点数 <17 要牌，否则停牌；软点数 <18 要牌，否则停牌；21/爆牌自动结束。用 0.8–1.6 秒可取消的服务器时间延迟表现思考，不能在浏览器后台自动发多次牌。

AI 决策函数只接收自己的手牌、合法动作、时间状态；**不接收对方手牌、完整牌堆或下一张牌**。它与真人使用同一发牌和结算代码。不承诺数学最优策略。角色化寒暄可以用既有对话能力，但不应阻塞牌局或每张牌收费调用模型。

## 6. 记忆翻牌小游戏

休息室侧桌单人游玩，4×4、8 对图案。每次翻两张，相同则保持翻开；不同则 800 ms 后盖回。结算显示用时和翻牌次数，无主线奖励、不存全服排名。

只需本机状态；刷新可重新开始并清楚提示，不伪称跨设备保存。主线切幕立即结束此本地游戏。所有图案都有辅助名称，不能只靠颜色识别；降低动态效果时取消翻转动画。两张比较期间禁止第三次翻牌，快速点击同一张不算配对。这个局部小游戏不占用 AI 的主线行动租约。

## 7. 视觉方案和具体改动

### 7.1 已实际查看的旧版问题

根据 test-results 中公网搜证、手机截图进行视觉检查：

- 大片明亮草地、地板反复平铺，场景缺乏道路、边界变化和叙事焦点。
- 家具与树木稀疏，书架贴在墙上更像图标，缺少房间结构和前后遮挡。
- 玩家过小；多个名字挤在一起，人物动作与朝向不充分。
- 页面上方阶段/说明占较多高度；手机把整张大地图等比缩小，文字和交互目标难读。
- 草地亮度与深色案件界面割裂；不是再换一组按钮颜色就能解决。

这些是视觉评审结论；本轮不会把文档样板标为已完成的游戏。

### 7.2 统一方向

“雨夜庄园、暖灯与冷庭院”。保留案件名称与深色基调，基础地图保持像素网格、人物明确朝向；暗部不覆盖证据文字。新包必须按同一像素密度和视角选择，宁可精修同一套也不混搭五种人物比例。

颜色目标：深夜蓝 #14212B、室内木色 #6E513B、灯光琥珀 #E6B96A、石墙 #66727B、庭院绿 #526449、牌桌绿 #214D43、纸面 #F1E6CD。正文至少 16px、常用标签至少 14px；颜色之外增加图标、边框和文字状态。

- 大厅：明确的中央长桌/地毯；侧边书柜、壁灯、窗；四个人物座位；左右门轮廓与地面通路。
- 庭院：石路连接门与搜证点、花坛/矮篱界定区域；树群形成留白边缘而非平均撒树；避免装饰盖住证据。
- 岸边：水岸转角和水面细波，岸石、芦苇和足迹；可走区域与危险水面明显区分。
- 书房：完整书柜、桌椅、地毯、纸张和灯；物件密度围绕可调查点组织。
- 会客室：双座、暖灯、门牌和占用提示，保持两人私人对话感。
- 休息室：中央绿色牌桌、两个座位、侧边翻牌桌和等候区；开牌动画、分数板与退出入口清楚。

### 7.3 渲染、人物和反馈

地面 → 地面装饰/地毯 → 按脚底 y 排序的人物与家具 → 前景墙/树冠遮挡 → 低强度光照 → DOM 标签和操作 UI。碰撞区域取物件实体基础而不是整张透明图片；前景不会拦截按钮。

人物必须核验真的有四方向 idle/walk 帧；左右翻转不能代替背面。静态肖像包只能做头像/候选角色。角色改色、衣服区分属于后续制作项，不能把下载了一个角色包写成四个案件角色已制作好。行走按距离驱动循环，停步回 idle，动画速度不影响权威移动速度。

搜证用明确的地面高亮和邻近提示，按键后短进度/声音反馈，成功才打开证据；失败显示原因。牌面优先保证 A/K/数字与花色清晰，统一背面，不用长条拉伸扑克牌。动画约 120–240 ms，提供降低动态效果设置。

### 7.4 桌面与手机

桌面主画面占可用宽度约 70%，右侧聊天约 30%；顶部只保留阶段、计时和准备等关键动作。角色本/证据/牌桌使用可关闭面板，不让大段说明长期压在地图上。

手机改为跟随人物的局部视口，保持角色显示高度至少 28px，不再缩小整幅世界到文字无法阅读。方向键/交互键固定在地图边缘；聊天、角色本、证据使用底部抽屉切换，支持键盘弹出和安全区域。21 点切为专用牌桌面板，自己的牌和要牌/停牌按钮始终在首屏范围。触摸目标至少 44×44px。

## 8. 数据、同步和迁移方案

复用现有 D1 和鉴权，不新增外部服务。下列均为拟新增契约，尚未生成迁移或修改运行设置：

| 数据 | 最小内容 | 同步与隔离 |
|---|---|---|
| npc_tasks | room/player、phase、version、mode、goal、path、startedAt、速度、lease、dueAt、自动调用数 | 公开视图只给路线/状态；隐藏材料和模型输入不下发 |
| room_settings | 房间规则版本、自主开关、小游戏开关、主线暂停信息 | 新房间快照默认值；旧房间继续旧规则，不中途强制升级 |
| space_reservations | room/space/player、phase、token、expiresAt | 会议室邀请的限时预留；进门与普通占用共同计入容量 |
| activity_sessions | room/table、revision、状态、两席、round、比分、牌堆/两手牌、deadline、请求结果 | 服务端保存全状态，按当前身份返回自己的牌；旁观仅摘要 |

可采用现有 rooms.body 保存小型房间设置；NPC 和牌桌用独立表避免每一步动作争抢主线 revision。最终迁移在实现时从 schema 生成并审查，保留已有 0000–0003 不改写。

会议室预留自接受邀请起最多30秒，失效后NPC只能到门口重新检查，不能强行进入。容量计算为实际在场人数+未过期预留（同一人不重复计数）；进门时在同一条件事务中消费预留并写入位置。暂停/换幕取消预留，牌桌预留则放在activity_sessions中。

活动共享一个小型房间执行版本：入座、切幕、超时、NPC 新任务对 phase/version 作条件校验，D1 batch 内的后续写入要依赖前一条件写成功。不得先扣 AP 后发现状态冲突，或牌桌已经取消却仍结算加分。牌局最多保存本场有限 requestId 响应，结束后按既有保留策略清理，避免无限 JSON 增长。

拟 API：`POST /api/npc/tick`（认领到期任务）、`POST /api/npc/control`（房主暂停/恢复/召集）、`POST /api/activities/action`（sit/invite/accept/ready/hit/stand/leave），均同源 Cookie + Origin + payload 校验。NPC tick、牌桌动作单独限流，不挤占聊天限流。

牌局状态随原轮询返回授权摘要与当前参与牌局；卡牌不走 P2P。NPC 路径版本由服务器下发；P2P 只可做刷新提示，不能由真人伪造 NPC 身份。正文、牌堆、密钥仍禁止静态服务或日志泄漏。

## 实施落地记录（2026-09-12）

用户批准后按此方案实现，以下是为当前四人规模采用的具体结构与美术实现：

1. 新房间默认自主模式，创建页可关闭；旧房间继续手动模式。地图/动作/角色本沿用原规则，没有新引擎或第三方服务。
2. simulation按房间保存3个NPC的状态、路径、模拟时钟和会客室预订；activities保存当前牌桌。它们各自有revision。NPC普通移动不触碰主线revision，搜证/分享/发言使用原主线CAS事务。D1租约防重复驱动，前台客户端2秒触发。
3. 主线合法目标由程序从角色过滤视图选择；大模型用于阶段发言、秘密指控、@和私聊。没有把每一步移动或每一次要牌交给模型。模型无法获得牌堆、别人手牌或未解锁材料。
4. 配置细节见SETTINGS：阶段投票模型调用受45秒间隔与预算约束，无可用模型时不伪造正确答案，等待原投票截止。
5. 扑克为两人比点三局，无下注。客户端只收到自己的牌，揭牌后对局双方看完整手牌；旁观者只看座位比分。
6. 4×4翻牌在当前浏览器运行，不计主线收益；离开休息室或主线推进则结束。
7. 美术使用Kenney CC0地图与扑克牌，加本次生成的四方向人物。精确裁切矩形在scene.js；程序步幅动态并非传统8帧sprite动画，未假称下载包已包含四个不同案件人物。默认静音，减少动态开关可记忆。
8. 手机使用固定比例跟随镜头，聊天抽屉与随身工具；桌面地图和聊天并列。

实际验收记录持续更新在STATUS，不用本方案的目标表冒充已通过测试。
